# Onboard report: map first, then sections

Status: in progress (2026-10-22). Branch `feat/onboard-report` from `main`. Grilling
and review done; plan approved (`~/.claude/plans/atomic-puzzling-minsky.md`).

## Goal

`onboard` writes one report that reads top-down: an index of the repo's parts, an ASCII
graph of how they relate, then one section per part, so the reader grasps the whole at
once and can dive into any part. Today step 3 gives a graph, a few sentences, and three
risks; graph nodes are not numbered and lead nowhere. Design is repo-agnostic.

## Decisions

Numbers are the order decided; later ones revise earlier ones where noted.

1. **One section per numbered part**, same `[n]` in every part of the report.
2. ~~Numbering lives in codemap's `INDEX.md`~~ — superseded by 9 and 10.
3. **All sections up front in a fixed block;** picking a number is the deep dive (reads
   that part's files, shows its flow, risks with evidence, then asks for a task). Deep
   dives are chat only.
4. **Index and relationships are separate parts.** Order: `## 1. Index` →
   `## 2. Relationships` (ASCII graph only, verb on each arrow, legend citing
   `file:line` per edge) → `## 3. Sections` (`### [n] Name`). Reason (user): the index
   lists what exists; the graph alone shows how parts relate.
5. **Sections carry no relationships:** What / Key files / Risks / Read first (Risks in
   chat only, per 15).
6. **Entry = component, at most 12:** a file, folder, or `file:line-range` with one job.
   Above 12, group into a parent entry; members listed unnumbered in its Key files and
   detailed in its deep dive. Every entry names a key file. The graph may also hold
   unnumbered external nodes like `(Postgres)`; their edges still cite a file.
7. **Risks sit in their part's section;** an "Across parts" list (≤3) after Part 3 holds
   risks spanning several parts or none, each naming parts and files.
8. **Verify by trials;** see *Checks*.
9. **The report is the only output, saved as one file.**
10. **`codemap` folds into `onboard`, then is removed.** `facts.py` moves to
    `skills/onboard/`; its test stays in `tests/` as `test_onboard_facts.py`. The
    `skills.lock` `codemap` entry is renamed `onboard` (ECC-derived text) and the ECC
    `LICENSE` copied into `skills/onboard/`.
11. **File rules.** First line `<!-- Generated by onboard: YYYY-MM-DD -->`. A file at the
    path without the header is never touched; ask. Non-interactive: write nothing,
    report in chat. The report is also printed in chat; "Pick a number to dive in, or
    name a task." is chat only.
12. **Flow: facts → read key files → `architect` risks → write report → deep dive or
    named task.** Locate, look up, and plan leave the flow. Opening keeps 2–3 lines:
    what the repo is, how it runs, how it is tested. `onboard` neither reads nor deletes
    old `docs/CODEMAPS/`.
13. **Remove `documentation-lookup`; keep `iterative-retrieval` and `blueprint`
    unchanged.** `install-skills.py` already removes links to deleted skills.
14. **Always rewrite on each run** (over reuse-by-commit). Reason: simple, always fresh.
15. **No risks in the file** (over saving non-security risks). File sections are What /
    Key files / Read first; Risks and "Across parts" are chat only. Reason: the file
    may be public; risks go stale; `architect`'s chat-only rule stays intact.
16. **Path `.agents/onboarding.md`** (over `docs/ONBOARDING.md`). Reason: no collision
    with hand-written guides, never published by a docs site. A loose `.md` in
    `.agents/` is not loaded as a skill.
17. **Triggers:** `onboard` adds "map this codebase", "give me an overview of this
    repo", "how does this repo fit together"; no "codemaps" phrases.
18. **Context7 `description` carries the lost rules** (`tools/mcp/servers.json:9`), e.g.
    "Current library docs; use for any library or framework question, matching the
    version the repo pins; never put secrets in queries." Reason: Pi shows only this
    line, not server instructions (`upstream/docs/pi/mcp.md:74,205`). Document the gap
    in `docs/how-it-works.md`. `apply-mcp.py` adds only missing servers (`:88-92`), so
    on this machine re-add `context7` in Pi once (`pi mcp remove context7`, then
    `ai-dotfiles`); new machines get it automatically.

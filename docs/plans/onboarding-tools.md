# Onboarding tools from everything_claude_code (ECC)

Status: active

## Goal

Bring the codebase-onboarding pieces in `reference/everything_claude_code/` into this
repo as shared tools that work the same way in all four CLIs (Claude, Codex, Pi, Antigravity).

## Decisions

1. **Required list:** `update-codemaps` command, `generate.ts` script, `doc-updater`
   agent, `architect` agent, `iterative-retrieval`, `documentation-lookup`, `blueprint`.
   Dropped: `search-first`, `exa-search`, `deep-research`.
2. **Self-contained:** a kept tool must not call or mention anything outside the kept set.
   Checked: none of them call the dropped items. These references are left to strip
   during the port:
   - `doc-updater`: `/update-docs` (not in the set); `npx madge` and `npx jsdoc2md`
     (also in `generate.ts`)
   - `iterative-retrieval`: the "Related" section (`continuous-learning` skill, ECC agents,
     external link)
   - `blueprint`: the ECC installation and update section, `~/.claude` path, `/blueprint`
     slash command, and "Claude Code" requirement
   - `documentation-lookup`, `iterative-retrieval`: `origin: ECC` frontmatter

3. **Packaging: five skills plus an `onboard` entry skill.** `codemap` (the command,
   doc-updater steps, and the generator), `architect`, `iterative-retrieval`,
   `documentation-lookup`, `blueprint`; `onboard` runs them in order: map, assess,
   locate, look up, plan. `install-skills.py` already links every folder under `skills/`
   that has a `SKILL.md`, so the installer needs no change.

4. **Generator: rewrite `generate.ts` in Python** (3.11+, standard library only), inside
   the `codemap` skill folder, with patterns for Python, Go, and Rust as well as JS/TS, and
   `unittest` tests in `tests/`.

5. **Provenance: lock all five ported skills in `skills.lock`** (`onboard` is new and not
   locked). `path` may be a list; `codemap` watches `commands/update-codemaps.md`,
   `agents/doc-updater.md`, and `scripts/codemaps/generate.ts`. `report-upstream.py`
   `section_skills()` learns list paths, with a test. Pin the ECC commit that matches
   the `reference/` copies (find it with `gh api`).

## Findings: what ECC's codemap generator actually produces

Ran `generate.ts` (Node 23, no download) on scratch copies of `cnc_page` (Next.js) and
`ai_dotfiles` (Python and shell), 2026-10-21.

- Always writes six files to `<cwd>/docs/CODEMAPS/`: `INDEX`, `frontend`, `backend`,
  `database`, `integrations`, `workers`. Empty areas still get a ~39-line file; 4 of 6
  were empty in both repos.
- Classifies by path regex only; reads no file contents. "Data Flow" and "External
  Dependencies" are fixed placeholder text; no routes, imports, or dependencies.
- Misclassifies: `favicon.ico` listed as a 31-line frontend module; `skills/learn/hooks/`
  counted as frontend (matches `/hooks/`).
- `INDEX.md` is mostly a 3-level file tree (~100 of 128 lines), including `.claude/`,
  `.gemini/`, `.github/` noise.
- Small bugs: stray backticks in the Architecture block; regenerate hints point to
  `npx tsx`, `madge`, `jsdoc2md`.
- Overwrites without a check: no preview, no `<!-- Generated -->` marker (uses
  `**Last Updated:**`), no 30% diff rule. Those rules exist only in the command text.
- Its six files differ from the command's five (`architecture`, `backend`, `frontend`,
  `data`, `dependencies`): in ECC the script is a skeleton and the agent writes the real
  content.

6. **Generator role: collect facts; the agent writes the maps.** The Python script reads
   the repo and prints a compact summary to stdout (language mix, manifests and their
   dependencies, likely entry points, a trimmed tree, per-directory file counts); it
   writes no files. The skill has the agent read key files and write maps in the
   command's format, only for areas that exist, **plus an ASCII graph of the whole map**.

7. **ASCII graph: the agent draws it from what it read.** No import scanning in the
   script; the agent draws the architecture from entry points and key files. The skill
   asks it to draw only edges it saw in a file and to name that file, so the graph
   stays checkable.

8. **Map output: `docs/CODEMAPS/` in the target repo, committed.** `INDEX.md` holds the
   ASCII graph and links; one map per existing area (`architecture`, `backend`,
   `frontend`, `data`, `dependencies`). Each starts with
   `<!-- Generated by codemap: <date> -->`. On re-run the agent summarizes what changes
   before writing and never touches a file without that header.

9. **`blueprint`: port from the real source, `antbotlab/blueprint`** (MIT, pinned
   `07c5b305cf2d95d584a0d0398c390e839fec5954`), not the ECC description. The ECC copy is
   only a 105-line summary. Port `SKILL.md`, `references/` (anti-patterns, both plan
   templates, review checklist), and `workflows/` (plan-mutation, resumption); skip
   `examples/` (48 KB). Lock it with a list `path`. Adaptations:
   - plans in `docs/plans/<task>.md` with this repo's task-file fields (status, goal,
     decisions, next step) plus blueprint's per-step briefs; not `plans/<project>-<slug>.md`
   - "Required: Claude Code" removed; `CLAUDE.md` → the project's `AGENTS.md`/`CLAUDE.md`
   - `memory/MEMORY.md` steps dropped (not a shared convention)
   - model tiers named generically (strongest/default), no Opus/Sonnet/Haiku names
   - review: a strongest-model sub-agent where the CLI has one; otherwise the same
     checklist runs in-session, and the skill says so

10. **Scope check: keep the full set in the `onboard` flow.** Reviewed each tool against
    onboarding a new repo: `codemap` and `architect` are the core; `iterative-retrieval`
    is a medium fit; `documentation-lookup` and `blueprint` are weak fits (Context7
    already covers lookups; blueprint is for after onboarding). The user kept all five in
    the flow: map → assess → locate → look up → plan.

11. **`architect`: a lean assessment skill.** Reads `docs/CODEMAPS/` first (or suggests
    `codemap`), then key files; reports current structure, debt, and red flags in chat,
    each naming its source file. Writes an ADR only when the user decides something, in
    the repo's own ADR folder and format (asks if the repo has none). Keeps the review
    process, checklist, and red flags; drops the generic pattern lists, the SaaS example,
    and the fixed ADR template.

12. **`iterative-retrieval`: a search loop the agent runs itself.** Keep the four phases,
    0–1 relevance scale, stop rule (≥3 files ≥0.7 and no critical gaps, or 3 cycles), and
    both worked examples. Replace the JS pseudo-code with plain steps using the CLI's own
    search and read tools. Add one section on handing found files, with reasons, to a
    sub-agent where the CLI has one.

13. **`documentation-lookup`: light port tied to the repo.** Keep the steps, 3-call limit,
    and secrets rule. Add: take library versions from the repo's manifests (listed by the
    codemap fact summary) and use the matching Context7 version ID. Keep one example of
    three.

14. **`onboard` flow: map and assess, then stop and ask.** Runs `codemap` then `architect`,
    shows a short briefing (what the repo is, the ASCII graph, top risks), then asks what
    to work on first. Locate, look up, and plan run only for a named target; `blueprint`
    only when the task looks multi-PR. Triggers: "onboard me", "onboard this repo",
    "help me understand this codebase".

15. **Branch: `feat/onboard` from `main` in a separate git worktree.** The uncommitted
    `feat/learn` work stays untouched; separate PRs. Test in the worktree (unit tests,
    shellcheck, installer preview); the live install runs from the main checkout after
    merge. The healthcheck already checks every `skills/*/SKILL.md` link, so it needs no
    change.
16. **Trial runs:** Claude Code onboards `forks/ai/dotfiles` (Nix config: `flake.nix`,
    `home.nix`, `bootstrap.sh`; no JS/Python manifest); Codex onboards
    `forks/ai/superpowers` (JS `package.json`, skills, hooks, existing `docs/`). Both
    clean git checkouts with no `docs/CODEMAPS/`. Pass: maps only for areas that exist,
    each with the generated header; every ASCII-graph edge names a real file; every
    `architect` finding names its source file. Plus unit tests (facts script on fixture
    repos; list `path` in `section_skills()`), `unittest`, `shellcheck`, installer
    preview, and healthcheck after merge.

17. **Trials run in place on an `onboard-trial` branch** in each fork; afterwards show
    the diff and let the user keep or delete the branch.
18. **ECC pin: `affaan-m/everything-claude-code` at
    `0be6455fca4cab1ba1aac600c68184f9256c283d`** (2026-03-16, MIT). All seven
    `reference/` files match their blobs at that commit (checked with `git hash-object`
    against `gh api …/contents?ref=`). Only `report-upstream.py` reads the lock
    (`section_skills()`, `entry['path']`).
19. **Facts script interface (frozen before parallel work).**
    `python3 <codemap skill folder>/facts.py [ROOT]` (default `.`), standard library
    only, Python 3.11+. Writes nothing; prints Markdown to stdout; every path is relative
    to ROOT; target ≤ ~300 lines. File list from `git ls-files` (tracked + untracked,
    not ignored) when ROOT is in a git repo, else a walk that skips noise dirs (`.git`,
    `node_modules`, `dist`, `build`, `out`, `.next`, `.nuxt`, `target`, `vendor`,
    `.venv`, `venv`, `__pycache__`, `coverage`, `.cache`, `.turbo`). Sections, in order:
    - `# Repo facts: <ROOT name>`: file count, whether git, today's date
    - `## Languages`: language | files | lines, from extensions; unknown extensions as
      `other (.ext)`; top 15
    - `## Manifests`: per manifest file, its path, name/version if declared, runtime
      and dev dependencies with version specs. Covers `package.json`, `pyproject.toml`,
      `requirements*.txt`, `go.mod`, `Cargo.toml`, `flake.nix` (input names and URLs)
    - `## Entry points`: candidates with the reason each was picked (manifest
      `main`/`bin`/`scripts`/`[project.scripts]`, `__main__.py`, `main.*`, `index.*`,
      `app.*`, `cli.*`, files in `bin/`, executable top-level scripts, `Makefile`,
      `Dockerfile`, `flake.nix`)
    - `## Tree`: directories only, depth ≤ 3, each with its file count
    - `## Docs`: `README*`, `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, files under `docs/`
      (ADR folder named if found), and each `docs/CODEMAPS/*.md` marked `generated` if
      its first line starts with `<!-- Generated by codemap:`, else `hand-written`
20. **Trial loading: temporary links for the six new names only.** Link `onboard`,
    `codemap`, `architect`, `iterative-retrieval`, `documentation-lookup`, `blueprint`
    from the worktree into `~/.claude/skills/` and `~/.agents/skills/` (none exist there
    now, so no existing link changes); remove them after the trials so the installer
    creates them after merge. Tests the real trigger ("onboard me").
21. **Re-run rule (revises decision 8).** A direct request ("update the codemaps") is the
    yes for generated maps: update, then list what changed. Ask first only when an
    update comes up as a side effect (e.g. inside `onboard`). Files without the header
    are never edited, renamed, or deleted, even on a direct request. Reason: trial 3
    (non-interactive Codex) rewrote generated maps on "update the codemaps" despite the
    ask-first rule; generated maps are regenerable and in git, hand-written ones are not.

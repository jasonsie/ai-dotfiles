---
name: onboard
description: Get to know an unfamiliar repository. Maps the codebase, assesses its structure, gives a short briefing, then asks what to work on first and finds the code, docs, and plan for that. Use when the user says "onboard me", "onboard this repo", "help me understand this codebase", or opens a repository they have not worked in before.
---

Onboarding runs five steps. Each is its own skill; this one only sets the order and
the stopping point.

```
map ──▶ assess ──▶ briefing ══ stop and ask ══▶ locate ──▶ look up ──▶ plan
codemap  architect                               iterative-  documentation-  blueprint
                                                 retrieval   lookup
```

## 1. Map

Follow the `codemap` skill. It runs the facts script and writes `docs/CODEMAPS/`
with an ASCII graph of the whole repository. If current maps already exist (they
carry the `Generated by codemap` header), read them instead of regenerating, and
say how old they are.

## 2. Assess

Follow the `architect` skill: structure, technical debt, and red flags, each naming
the file it came from. Write no ADR here; nothing has been decided yet.

## 3. Briefing, then stop

Give the user a short briefing in chat:

- what the repository is for and how it runs, in two or three sentences
- the ASCII graph from `docs/CODEMAPS/INDEX.md`
- the top three risks or surprises from the assessment
- where the maps were written, and whether they are new or updated

Then ask: **"What do you want to work on first?"** Do not go on until the user
names a feature, bug, or task. Do not invent one.

## 4. Locate

For the named target, follow the `iterative-retrieval` skill to find the files that
matter, using the maps from step 1 to choose where to search first.

## 5. Look up

If the target depends on a library or framework, follow the `documentation-lookup`
skill, using the versions the repository pins.

## 6. Plan

If the work looks like several pull requests or several sessions, follow the
`blueprint` skill. Otherwise, summarise the files found and the first change to make,
and stop.

## Rules

- The repository's own `AGENTS.md` or `CLAUDE.md` overrides anything here.
- Steps 1 and 2 may write only `docs/CODEMAPS/`. Ask before writing anything else.
- Steps 1 and 2 read; they do not run the project's tests, builds, or installs.
  Say how the project is tested instead.
- If a step's skill is not installed, say so and do that step by hand, briefly.
